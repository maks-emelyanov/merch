# Security policy

This application can store marketplace credentials and publish products. Use fake providers and dry-run publishing for development and CI. Keep `.env` and production artifacts outside version control, and rotate any credential that is exposed.

Report suspected vulnerabilities privately through GitHub's **Security** tab when private vulnerability reporting is enabled. If it is unavailable, contact the repository owner privately before posting details in a public issue. Include reproduction steps, the affected version or commit, and the expected impact; redact credentials and customer data.

Security fixes are evaluated against the current main branch. No response-time or long-term support commitment is offered.
